# 武器与弱点伤害

武器在购买、制作、剧情取得或开局生成时得到固定整数百分比。数值存入 `item.weapon`，作用于敌人最大生命值，不是固定生命点数，也不是相对普攻的乘数。旧武器按稳定实例编号补齐一次；之后读档、换装、修改描述都不重掷。不同获得批次的武器保留独立实例。

| 品质 | 刀剑及近战武器 | 枪械 |
| --- | --- | --- |
| 粗制 | 2%–4% | 5%–9% |
| 普通 | 5%–10% | 10%–20% |
| 精良 | 11%–15% | 21%–25% |
| 珍稀 | 16%–20% | 26%–30% |
| 非凡 | 21%–25% | 31%–35% |

AI 只能在首次登记时按剧情依据提供 `weapon: { kind, quality }`，不能指定 `bonusPercent`。数值由本地生成。所有武器共用一个装备槽；携带、叠放、多次装备不会叠加伤害。枪械在同一品质下通常更强，普通档最低枪械与最高刀剑均为10%。此功能不新增弹药或耐久规则。

武器加成适用于普通攻击，以及本地规则有 `weaponAttack: true` 的能力。目前是战士途径的武器精通和守护反击。狼人利爪、法术、治疗、符咒及持续伤害不附加武器伤害。

## RP 弱点攻击

玩家需在本轮明确描述攻击具体部位。AI 根据敌人的生理结构、当前防护、弱点暴露情况与攻击方式判断能否利用它。成立时，在该次 `combat.action` 或直接伤害 `ability.use` 中提交 `weakPoint: { name, evidence }`，本地额外奖励5个百分点。省略判断时没有奖励；只泛称“攻击弱点”、描述并未攻击该部位或填写任意伤害数值均不能取得奖励。

判断依据记录在结果与变更日志，奖励只针对本次直接攻击，不能叠加或存为持续增益。AI 负责情境判断，本地校验负责玩家意图、字段、固定奖励和结算边界；本地引擎不会自行从敌人名称推断真实解剖结构。快速模式草稿须等待最终结算才能确定弱点效果。

```
伤害比例 = min(60%, (基础比例 + 适用武器比例) × 1.2^强化层数 + 本次弱点奖励)
防御中的敌人再将此比例减半。
最终伤害 = ceil(敌人最大生命值 × 伤害比例)，不超过敌人剩余生命。
```

例如敌人最大生命100，普通攻击12%，已装备左轮附加15%：正常攻击27点；明确射击暴露眼部且AI确认成立时为32点。下一次普通攻击恢复为27点。若先强化两层，再获弱点奖励，比例为 `(12+15)×1.44+5 = 43.88%`，最终一次向上取整为44点。

行囊显示固定值，战斗预览显示当前武器、基础比例、强化、防御与上限；预览不提前计入尚未经过AI判断的RP奖励。最终日志和AI结算上下文使用同一份本地结果。

验证：`node --test tests/weapons.test.mjs`；开发服务器运行后可执行 `node scripts/test-weapons-browser.mjs`。浏览器脚本通过模拟AI响应验证普通/快速模式接线，不代表对真实模型判断质量的评估。
