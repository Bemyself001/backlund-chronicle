# 通用任务引擎

任务系统分为四层：内容声明阶段、条件及风险；AI 提出带玩家原话的行动结果；本地引擎验证并结算；剧情和手记只呈现确认后的记录。此规则通过固定 system 消息注入，不依赖可编辑的世界提示。

## 运行接口

`quest.resolve` 接收 `instanceId`、`actionQuote`、`outcome`、`evidence`。可选 `start` 用于明确追查一个已经可见的事件。`outcome` 为 `progress`、`blocked`、`failed` 或 `recover`。普通自定义任务使用 `quest:原任务ID`，通过 `quest.add` 注册名称、摘要和当前目标，使用 `nextObjective` 更新当前目标。

预定义任务的 `steps` 最多三个，每项包含当前允许的 `objectiveId`、玩家原话和完成证据。逐项核验、逐项结算，后一项条件不足时保留此前成功的步骤，并将受阻原因返回给叙事。每个实例每轮最多三个普通步骤，跨工具调用也不能突破。自然语言匹配只替代普通步骤的关键词限制，不替代地点、物品、事实、状态、时间窗口等条件。带否定、假设的意图不能作为完成证据。关键步骤继续遵守明确行动词与拒绝词。

原 `trigger.engage`、`trigger.progress`、`trigger.abandon` 以及基于 `advanceWhen` 的事实信号保持兼容。事实信号任务仍通过物品、线索等对应工具产生本地事实。奖励去重沿用触发引擎。特殊行动委托不允许 AI 改写结算，由原有特殊行动引擎处理。

## 统一记录和存档

`questRuntime.js` 将触发实例、历史实例和普通任务投影到 `questJournal`（独立格式版本 1）。开始、推进、结束及读档时均补齐记录；保存名称、摘要、当前目标、状态、阶段和修订号。手记不再截取最近五个特殊任务，已结束记录持续保留。旧存档自动补齐，不重发奖励、不重置倒计时。

`questJournal.attempts` 持久化各任务的当前阶段、最后结算轮次、停滞次数和恢复线索。同轮重复结算不增加计数；当轮成功推进优先于此前受阻；换阶段或确认推进后清零。只有带任务关联的工具结果计数，休息和无关探索不计数。

## 停滞与失败

两次相关行动无进展，显示明确的当前目标与条件提示。第三次提供可执行的整理证据/请教路线。普通阶段的一次明确失败也可提供这条路线。玩家选择后以 `recover` 提交实际新线索，本地确认耗时 20 分钟，将线索写入当前任务并清零停滞计数；不自动完成目标、移动角色或发奖。每阶段恢复路线最多使用一次，真正取得进展后才重新开放，防止反复空转。

AI 负责判断语义及创作线索；本地引擎负责硬条件。它不尝试仅靠字符串证明模型叙述的世界事实，因此必须仍由现有工具核验永久事实与状态变化。恢复线索本身不会成为条件事实。

## 风险边界

阶段可声明 `finale`、`dangerous`、`majorDecision` 或 `irreversible`。含倒计时的阶段自动隔离。隔离阶段不允许合并结算、不提供保证突破的恢复路线；只能澄清已知目标与后果。进入这种阶段后，下一步需另一次行动。旧任务快照也继承当前内容声明的更严格风险标记。

家传怀表从货栈炸弹起的终章、撤退重返和最终对峙标记为终章；潜入、治疗选择及危险雷管等另行标记。数据只声明边界，执行规则位于通用引擎，不含具体剧情 ID。

## 呈现与验证

任务修订及提示等级变化会产生持久化的叙事事件，要求正文回应本地结果，同步当前任务的三个选项。已有专属事件（如怀表的图书馆/商会街路线）优先使用专属选项。生成失败不确认送达，下一次可重试；重复读档不重复播报。

回归测试覆盖自然语言等价行动、连续推进的局部成功、前置条件、停滞阈值、时间代价、重复请求、终章限制、旧快照、手记补齐、历史保留与提示同步。APK 包含与网页相同的引擎模块，发布沿用现有包名及签名。
