# 系统、内容与存档边界

## 三层职责

这是第一阶段的内置内容与规则拆分；尚未开放外部内容包导入或多世界切换。系统提示词与 API 默认设置仍保留现有入口，后续可继续拆细。

- `src/content/backlund/`：贝克兰德固定内容。只放可序列化的数据定义，例如开局、地点、路线、天赋、途径与角色模板。
- `src/content/index.js`：当前启用内容包的唯一查询和校验入口。系统与界面从这里按稳定 ID 读取内容。
- `src/system/` 与 `src/engine/`：执行地图、开局、天赋、回合和工具规则。系统可以读取内容，内容不得导入系统。
- `src/services/storage.js`：玩家存档及迁移。AI 生成的地点、人物、物品和剧情属于玩家存档，不回写核心内容包。

## 版本

- `content.schemaVersion`：内容文件结构版本；读取器不兼容时必须拒绝加载。
- `content.contentVersion`：贝克兰德内容版本；用于追踪新档案采用的内容。
- `SAVE_VERSION`：玩家存档结构版本；由迁移函数负责兼容旧档案。
- 应用与 APK 版本继续由发布流程维护，不与以上版本混用。

## 内容规则

1. 所有地点、天赋和途径使用稳定且唯一的 ID；已发布 ID 不得改名复用。
2. 固定路线与开局只能引用内容包中存在的地点。
3. 内容值不能含函数、类实例或可执行脚本；效果仅使用系统认识的声明式字段。
4. 新内容默认只影响新档案。已写入存档的剧情、物品实例、动态地点和地图进度继续以存档为准。
5. 删除或改变已发布定义前，必须先增加对应的存档迁移与回归测试。
6. API 密钥属于用户设置，不进入内容包、游戏状态或导出存档。

## 依赖方向

`界面 / AI 服务 → 内容查询 + 系统规则 → 玩家状态`

内容包位于依赖链底部，不能反向调用界面、服务或引擎。`src/data/` 中与本次迁移同名的文件暂时作为旧导入路径兼容层，后续模块全部切换后再删除。
